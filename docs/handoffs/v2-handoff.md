## What the product is now (v2)
User types a plain-English want ("jewelers that use princess cut diamonds"), circles an area on a map, gets a ranked, web-verified list of businesses from the Colorado Secretary of State registry, with a one-page brief per lead. No profiles, no filters, no analytics tabs — those v1 features were deleted (git history keeps them).

## Pipeline (fetch → triage → verify → brief)
1. `deriveIntent(query)` — 1 LLM call → `SearchIntent {keywords, exclusions, requirement}`. Ephemeral; the query IS the profile. Fallback keyword extraction if unparseable.
2. `searchEntities` (registry-core) — keywords go INTO SoQL server-side (`upper(entityname) LIKE '%KW%'` + trade-name descriptions, zips chunked ×150). Only candidates leave the API. This fixed v1's metro-radius "load failed" (~300k rows client-side).
3. Classify — TSV batches of 30, concurrency 2, Y/N/U verdicts, cached (djb2 key: entityId|query).
4. Verify — per lead, web_search tool, concurrency 3, auto-verifies first 10; score clamped 0-100, strings capped (injection tests cover this: `tests/qualify/injection.test.ts`).
5. `assembleBrief` — pure template. `draftOutreach` — optional 1 call, user-triggered.

Orchestrator: `runSearch(opts)` in `packages/qualify/src/pipeline/search.ts`, emits streaming `SearchEvent`s (intent/candidates/lead/update/budget/error/done). Leads upgrade live.

## Key files
- `packages/registry-core/src/sources/colorado/search.ts` — server-side keyword search + `soqlSafeKeyword` (SoQL injection guard, SECURITY.md Threat 7)
- `packages/registry-core/src/location/zipCentroids.ts` — 527 CO zips, GENERATED by `scripts/gen-centroids.mjs --prefixes=80,81 --state=CO` (per-state recipe; never hand-edit)
- `packages/qualify/src/pipeline/{intent,classify,verify,brief,search}.ts`
- `apps/cli/src/claudeCodeBackend.ts` — LlmBackend shelling to headless `claude -p` (bills Max sub, WebSearch allowed for verify). Prompt via **stdin** (`--allowedTools` is variadic and eats positional args). ~15k tokens/call overhead from Claude Code's own system prompt — normal.
- `apps/artifact/src/App.jsx` — single screen: city → Leaflet map (runtime CDN load, click moves circle, radius slider, fallback text UI if blocked) → query → streaming list → brief panel.
- `scripts/bundle-artifact.mjs` — esbuild → `dist/artifact.jsx` (59kb, banned-string scan).

## Gotchas (hard-won, do not rediscover)
- Entity status `"Good Standing"` vs trade names `"GOOD"` — different datasets, different strings.
- `jurisdictonofformation` — typo in the government source, intentional.
- `within_circle()` doesn't work (no location column); radius = zip-centroid expansion.
- Datasets: entities `4ykn-tg5h`, trade names `u7sb-g482` (trade names have their own `zipcode` field).
- CLI runs via `npx vite-node` (plain node can't resolve `.js`→`.ts` imports).

## Validate / build / test
```
npx vite-node apps/cli/src/index.ts -- search "jewelers that use princess cut diamonds" --city=Denver --radius=5 --verify=3
npm test                          # 45 tests, all green
node scripts/bundle-artifact.mjs  # 59kb, clean
```
